# Architecture rules

- `apps/web` and `apps/server` may depend on `@deadline/shared` and `@deadline/domain`. Shared contracts never import applications/frameworks/adapters. Domain owns the sole business-rule implementation, schema, errors, and initial migration; it has no Node/native/browser driver imports. Web never imports server internals.
- Keep the React shell and task terminal usable before Phaser starts and when its asset loading or renderer fails. Game loading affects the canvas area only.
- Put Phaser simulation in `apps/web/src/game/`. React components mount/destroy the game at one adapter boundary; do not construct scenes in render functions.
- Use a typed, instance-scoped bridge for meaningful events and commands: interaction requested, pause/resume, mission outcome, authoritative resource snapshot. Avoid global event buses and per-frame React state. Dispose all subscriptions on unmount/shutdown.
- UI owns focus. Opening terminal/dialogue/pause suppresses gameplay keyboard and pointer actions; closing restores them only when the correct scene is active. Handle browser blur and hidden tabs.
- Request resource changes through the selected persistence adapter. Native requests go through Fastify; Pages requests go through the typed worker bridge. Both call `@deadline/domain`. Phaser may request a shot; it cannot mint ammunition, XP, reward history, or durable progress. The orchestrator owns shared contracts/domain integration.
- Keep API schemas, DTOs, errors, and version semantics explicit. Validate transport responses as well as requests. Never expose ORM rows as the accidental public API.
- TanStack Query caches authoritative native/browser snapshots; Zustand holds transient UI state; Phaser holds simulation state. After mutations, reconcile the returned authoritative version and invalidate affected queries. Do not apply stale responses over newer balances.
- Separate immutable mission/map definitions, scene lifecycle, entities, AI state, and services. Scene shutdown removes input, physics callbacks, timers, tweens, audio, and bridge handlers. Scene restart must not register them twice.
- Confine browser SQLite to `apps/web/src/persistence/`; React/Phaser must not issue SQL or modify IndexedDB directly. Run SQL.js in a worker. Hold one origin-wide Web Lock across reading the latest IndexedDB bytes, the SQLite transaction, and the durable IndexedDB write; respond only after storage completes. A failed flush must not become a confirmed mutation.
- Keep native SHA-256 request fingerprints compatible with existing receipts. Browser fingerprints may use the canonical request representation. Preserve mutation scope, payload binding, transaction boundaries, response revisions, and durable replay semantics across both adapters.
- Select persistence mode explicitly at build/configuration time. Do not fall back to a fresh browser profile when a native API fails. Pages needs no remote API, but browser profiles have no cross-device/native synchronization; clearing site data loses the profile.
- Keep resource reservations durable: commit each shot before it becomes effective, refund only proven unused rounds once, and recover interrupted attempts through explicit settlement. Worker teardown/reload cannot restore spent rounds.
- Keep clean-profile reset separate from story replay. Require explicit destructive consent and the exact confirmation token; retain settings, durable retry receipts, and monotonic revisions. Story replay never deletes real tasks/resources.
- Build Pages assets/worker/WASM with the repository base path. Never ship native database files or credentials. Keep runtime capability/storage failures visible; Web Locks and IndexedDB failures cannot silently disable persistence.
- Record cross-system choices in `docs/DECISIONS.md`. Use documented Node tool runners and Prettier commands. Public repository/Pages authorization is established, while actual deployment and new browser-mode test results require evidence in `docs/VERIFICATION.md`.
