# DEADLINE: 1989

**Заверши дела. Переживи ночь.**

Список настоящих задач внутри оригинального пиксельного экшена с видом сверху. Выполняйте дела, получайте патроны и опыт, затем отправляйтесь в старую типографию. Игра, смерть и обучение не меняют состояние ваших реальных задач. Интерфейс, обучение, диалоги и ошибки переведены на русский.

## Запуск

Нужны Node.js 24+ и pnpm 12.18.0; проверенная среда — Node 26.7.0. Команды выполняются из корня проекта.

```sh
npm install --global pnpm@12.18.0
pnpm install --frozen-lockfile
pnpm dev
```

Откройте **http://127.0.0.1:5173**. API работает на **http://127.0.0.1:3001**. Миграции SQLite применяются автоматически, без сброса данных.

Для готовой сборки остановите сервер разработки и выполните:

```sh
pnpm build
pnpm start
```

Готовое приложение и API доступны вместе на **http://127.0.0.1:3001**. Остановка — Ctrl+C.

В разработке база по умолчанию находится в `apps/server/data/deadline.sqlite`, при запуске сборки — в `data/deadline.sqlite` от корня. Чтобы использовать один профиль в обоих режимах, задайте один абсолютный путь:

```sh
DATABASE_PATH=/absolute/path/to/profile.sqlite pnpm dev
DATABASE_PATH=/absolute/path/to/profile.sqlite pnpm start
```

Для резервной копии остановите сервер. Для работающей базы используйте механизм резервного копирования SQLite: одного основного файла при включённом WAL недостаточно. Не удаляйте базу ради повтора обучения.

Двоеточие в имени текущей папки мешает обычному Unix PATH. Корневые команды используют прямые Node entry points через `scripts/workspace.mjs`; здесь следует запускать приведённые команды pnpm вместо `pnpm exec`.

## Задачи и награды

Терминал открывается у компьютера клавишей E или кнопкой «TAB ТЕРМИНАЛ» из меню, игры и экрана ошибки. Создавайте, редактируйте, выполняйте, открывайте повторно и удаляйте задачи. Доступны описание, сложность, срок, фильтры, статистика и квитанции о наградах. Размер терминала стабилен; длинные панели прокручиваются внутри окна.

| Сложность | Патроны | Опыт |
| --- | ---: | ---: |
| Лёгкая | 3 | 50 |
| Обычная | 6 | 100 |
| Сложная | 12 | 200 |

Награда выдаётся только за первое выполнение. Повторное открытие не стирает историю. Удаление ничего не начисляет и не забирает заработанное. При потере связи интерфейс сохраняет черновик и повторяет тот же запрос; несохранённые изменения не выдаются за подтверждённые.

## Задания и восстановление

После обучения открывается одна игровая локация: типография «НОЧНАЯ СМЕНА», четыре противника ближнего боя и два стрелка. Перед выходом выберите количество патронов. Можно выйти без патронов и пользоваться рукопашной. Одно попадание убивает игрока.

Сервер резервирует выбранные патроны. Каждый выстрел сначала сохраняет расход. После смерти или победы остаток возвращается один раз; выпущенные патроны не восстанавливаются. Победа сохраняет прохождение и лучшее время, смерть перезапускает противников. Настоящие задачи и опыт не меняются.

Обновление страницы во время боя открывает восстановление прерванного задания. Подтвердите завершение, чтобы вернуть только неизрасходованный остаток и проснуться в квартире. Повторное подтверждение не создаёт патроны. Терминал доступен и во время восстановления.

Абонент № 9 звонит по событиям обучения, смертей, побед и выполнения дел. Звонки необязательны; история, приоритеты и паузы между ними сохраняются.

## Звук и доступность

Оригинальные синтезированные музыка и эффекты меняются между меню, квартирой, терминалом, разговором, боем, смертью и победой. Браузер включает звук после первого действия пользователя. Настройки громкости, выключения звука, режима стримера, уменьшения анимации и ЭЛТ сохраняются в SQLite. Все поставляемые записи созданы для проекта; непроверенные внешние треки не используются.

У форм есть подписи, видимый фокус и управление с клавиатуры. Окна удерживают и возвращают фокус. Печать текста не управляет персонажем. Отказ игрового движка не блокирует задачи.

## Проверки

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:e2e
pnpm validate:bootstrap
node scripts/production-smoke.mjs
```

Последняя команда требует предварительной сборки и проверяет настоящий перезапуск готового сервера на порту 3005 с временной базой. Playwright использует отдельные порты 5174/3002 и временный профиль. Обычная база пользователя не затрагивается. Проверенная конфигурация использует `/usr/bin/chromium`; другой путь задаётся через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

43 модульных/API-теста и 7 браузерных сценариев проходят. Проверены настоящий бой до победы, смерть, пауза, повторные переходы и сохранение патронов. Отчёт и ограничения измерений: [VERIFICATION](docs/VERIFICATION.md). Скриншоты находятся в [docs/evidence](docs/evidence/).

## Устройство и материалы

```text
apps/web          React, Phaser и оригинальные ресурсы
apps/server       Fastify, Drizzle, SQLite и миграции
packages/shared   Проверяемые контракты API и игровой мост
```

React отвечает за интерфейс, Phaser — за симуляцию, Fastify — за правила и транзакции, SQLite — за постоянное состояние. TanStack Query хранит серверные снимки, Zustand — временное состояние интерфейса; кадры игры не вызывают обновление React.

Графика воспроизводится из `scripts/generate-art.py` с Python/Pillow, звук — из `scripts/generate-audio.py` на стандартной библиотеке Python. Для запуска игры Python не нужен. Источники, лицензии и происхождение: [ASSET_CREDITS](docs/ASSET_CREDITS.md), визуальные правила: [ART_BIBLE](docs/ART_BIBLE.md). Чужие игровые карты, персонажи, код и записи не включены.

Документация: [GDD](docs/GDD.md), [архитектура](docs/ARCHITECTURE.md), [решения](docs/DECISIONS.md), [задачи](docs/TASKS.md).

## Размещение

Это один локальный профиль на доверенном компьютере, сервер слушает loopback. Публикация в приватный GitHub распространяет исходники. Публичному многопользовательскому сервису нужны аутентификация, изоляция профилей и подходящее постоянное хранилище. Рабочая ветка — `feat/deadline-1989`, автоматического слияния в основную ветку нет.
